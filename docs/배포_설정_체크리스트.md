# 채팅·알림 배포/설정 체크리스트 (C1~C9, N1~N3 머지 후 조치)

코드 외 작업(런타임 설정·DB 마이그레이션·타 도메인 연계)을 한 번에 정리한 실행 가이드.
순서대로 진행하면 채팅/알림이 실환경에서 완전히 동작한다.

---

## 1. DB 마이그레이션 — 부분 유니크 인덱스 (필수)

`ddl-auto=update` 로는 부분 유니크(`WHERE ...`)가 생성되지 않으므로 **직접 실행**한다.
앱에서 활성 공지/코드 유일성을 앱 레벨로 보장하지만, 동시성 안전을 위해 DB 제약도 건다.

```sql
-- 채팅방 활성 공지는 방당 1건
CREATE UNIQUE INDEX IF NOT EXISTS uq_chat_notice_active
  ON chat_notice (chat_room_id)
  WHERE is_active;

-- 안심 커넥트 활성 코드는 코드값당 1건
CREATE UNIQUE INDEX IF NOT EXISTS uq_quick_connect_code_active
  ON quick_connect_code (code)
  WHERE status = 'ACTIVE';
```

실행(서버 예시):
```bash
docker exec -it twogether-postgres \
  psql -U <POSTGRES_USER> -d <POSTGRES_DB> -c "CREATE UNIQUE INDEX IF NOT EXISTS uq_chat_notice_active ON chat_notice (chat_room_id) WHERE is_active;"
docker exec -it twogether-postgres \
  psql -U <POSTGRES_USER> -d <POSTGRES_DB> -c "CREATE UNIQUE INDEX IF NOT EXISTS uq_quick_connect_code_active ON quick_connect_code (code) WHERE status = 'ACTIVE';"
```

## 2. 텔레그램 환경변수 (필수)

BotFather로 봇 생성 후 값 확보 → 환경변수로 주입. `application.yaml` 수정 불필요(@Value가 프로세스 env에서 읽음).

키:
```
TELEGRAM_BOT_TOKEN=123456:ABC-DEF...
TELEGRAM_BOT_USERNAME=udaegam_bot        # @ 없이 username만
TELEGRAM_WEBHOOK_SECRET=길고_랜덤한_문자열   # A-Z a-z 0-9 _ - (최대 256자)
```

- **서버**: systemd EnvironmentFile(`/home/ubuntu/postgres.env`)에 위 3줄 추가 → `sudo systemctl restart twogether-backend`
- **로컬**: 리포 `.env`는 docker-compose(포스트그레스)용이라 앱에 안 들어감 → IntelliJ 실행 구성의 Environment variables에 넣거나 `export` 후 `./gradlew bootRun`
- 미설정이어도 앱은 부팅됨(딥링크 username 공백·웹훅 secret 검증 비활성일 뿐)

## 3. SecurityConfig — 웹훅 permitAll (필수, global 파일)

텔레그램은 우리 JWT가 없으므로 웹훅 경로를 인증에서 열어야 한다. `global/config/SecurityConfig.java`:

```java
.authorizeHttpRequests(auth -> auth
    // ... 기존 permitAll 아래에 추가
    .requestMatchers(HttpMethod.POST, "/api/telegram/webhook").permitAll()
    // ...
    .anyRequest().authenticated()
)
```

이 한 줄이 없으면 텔레그램 POST가 401로 막혀 연결이 동작하지 않음.

## 4. Telegram setWebhook 등록 (공개 HTTPS URL 준비 후 1회)

요구사항: HTTPS(유효 인증서), 포트 443/80/88/8443, 외부 접근 가능.
우리 경로: `POST /api/telegram/webhook` → 예 `https://api.u-daegam.com/api/telegram/webhook` (실제 base path 확인)

```bash
# 등록
curl -s "https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/setWebhook" \
  -d "url=https://api.u-daegam.com/api/telegram/webhook" \
  -d "secret_token=<TELEGRAM_WEBHOOK_SECRET>"
# 성공: {"ok":true,"result":true,"description":"Webhook was set"}

# 확인 (url 정상, last_error 없어야 함)
curl -s "https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getWebhookInfo"

# 해제(폴링 전환/디버깅 시)
curl -s "https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/deleteWebhook"
```

로컬 테스트는 ngrok 등 터널 필요: `ngrok http 8080` → 발급 https 주소로 setWebhook.

### 엔드투엔드 확인
1. 앱에서 `POST /api/me/telegram/link-code` → 딥링크 수신
2. 딥링크 열어 봇 "시작(Start)" 탭 → 웹훅으로 `/start {code}` 전달
3. 서버가 code 검증 후 `user_telegram`에 chat_id 저장
4. `GET /api/me/telegram` → `linked: true`

## 5. 타 도메인 연계 (gathering 담당과 협의)

chat/notification은 연계 지점만 제공. 실제 호출/발행은 gathering 측에서 추가한다.

### 5-1. 모임 확정 → 채팅방 자동 생성 (C2)
`GatheringService.confirm()`에서 `gathering.confirm();` 다음:
```java
List<GatheringMember> members = gatheringMemberRepository.findByGatheringIdWithUser(gatheringId);
List<Long> memberIds = members.stream().map(m -> m.getUser().getId()).toList();
Long chatRoomId = chatRoomService.createGroupRoom(
        gathering.getId(), gathering.getTitle(), gathering.getHost().getId(), memberIds);
return new GatheringConfirmResponse(
        gathering.getId(), gathering.getStatus(), gathering.getConfirmedAt(), chatRoomId); // 기존 null → chatRoomId
```

### 5-2. 신청/수락/확정 알림 → 이벤트 발행 (N3)
알림이 필요한 지점에서 `NotificationRequestedEvent`만 발행하면 저장+인앱+텔레그램 발송됨:
```java
eventPublisher.publishEvent(new NotificationRequestedEvent(
        recipientUserId,                 // 알림 받을 사람(users.id)
        NotificationType.APPLICATION_ACCEPTED,
        "신청이 수락되었습니다",
        "'" + gathering.getTitle() + "' 모임 신청이 수락되었습니다.",
        Map.of("gatheringId", gathering.getId())   // 이동 대상 meta
));
```
- (선택) 공지 알림: chat `ChatNoticeService.register`에서 참여자 대상으로 같은 이벤트 발행 한 줄 추가 가능

## 6. 프론트 반영 사항
- 채팅 REST base 경로: `/api/chat` → **`/api/chat-rooms`**
- STOMP: 엔드포인트 `/ws-stomp`(SockJS), 구독 `/sub/chat/rooms/{roomId}`, 발행 `/pub/chat/rooms/{roomId}/send`, CONNECT 헤더 `Authorization: Bearer {token}`
- 실시간 알림 구독: `/sub/users/{userId}/notifications` (payload.kind = NOTIFICATION | CHAT_MESSAGE)
- 이미지 메시지: 클라이언트가 스토리지 업로드 후 URL을 `POST /api/chat-rooms/{roomId}/messages/images`로 전달

---

## 7. 후속(선택, 확장 시)
- 디바운서·QUICK_CONNECT TTL·프레즌스 → Redis 이전(다중 인스턴스 대비)
- 이벤트 스트림 → Kafka 아웃박스(알림/활동온도/AI 컨슈머)
- STOMP SUBSCRIBE 접근 제어(방/유저 토픽 권한) 인터셉터
- 인앱 푸시를 명세의 `/user/{id}/queue/notifications`로 쓰려면 WebSocketConfig에 `/queue` 브로커 + user destination 추가
